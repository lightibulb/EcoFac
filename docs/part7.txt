7. Known limitations.

· The audit_events table enforces append-only strictly at the application layer. The SQLite schema itself does not prevent manual DELETE or UPDATE statements if someone connects directly to the database.
· The EvidenceBuilder currently pulls the source_id from the historical readings, but does not explicitly include batch_id or created_at from the import batches. Future iterations may want to expand the JSON payload.

8. Any unresolved risks.

· Evidence JSON Size: If a detector used a very large window (e.g., window_size=8760 for a full year), the JSON string containing all historical readings could become quite large in the SQLite database. For the current MVP, this is acceptable.
