7. Known limitations.

· csv.DictReader loads rows sequentially, which is memory efficient. However, reading the whole CSV string to check max_size_mb at the start does momentarily load the file into memory. For future scaling to 100MB+ files, we would read the file stream in chunks.
· Database transactions are committed per file, not per row. If a catastrophic failure occurs (e.g., out of memory), the entire batch is rolled back. Row-level data errors are caught and skipped.

8. Any unresolved risks.

· Date parsing quirks: datetime.fromisoformat is strict in Python 3.11. Unusual but valid ISO-8601 formats (e.g., YYYYMMDD) will be rejected. This is generally a safe default for facility data.
· Missing optional fields: Currently, optional fields like outdoor_temperature and occupancy are ignored by the pipeline, as we have not yet implemented the models for them. They pass through harmlessly.
