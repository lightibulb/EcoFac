# Audit 2026-11-01

Scope: all Python source, schema, docs, CI and tests (templates and `.bak` files excluded).

## Data-integrity bugs fixed
- **Import crash on re-upload of negative readings:** the quality issue pointed at a reading that was skipped as a duplicate, violating the foreign key and failing the whole import. Issues are now written only for stored rows.
- **NaN / infinity accepted:** `float("nan")` broke the NOT NULL constraint; `inf` poisoned every statistic. Non-finite values are now rejected as `malformed_value`.
- **Rejected rows shadowed valid rows:** a row rejected for its unit still claimed its (meter, timestamp) key, so a later valid row was wrongly called a duplicate.
- **Mixed timestamp formats:** `+00:00` vs `Z` and optional microseconds broke string ordering (newest-first lists, window queries). Everything is now `Z`; stored reading times are whole seconds; `now_z()` always has microseconds.
- **`to_z` / `parse_utc` guessed local time for naive input** despite documented rejection. They now raise.
- **`/analyze` ignored offset timestamps** (`+00:00` never matched stored `Z` values) and **created incidents for quality-gated anomalies** while the docs and runner said they are not.
- **Duplicate incidents:** two detectors flagging one reading opened two incidents. They now share one incident with one evidence record each; `create_incident` is idempotent.
- **Race conditions:** imports, incident creation and transitions now use `BEGIN IMMEDIATE` and re-read state inside the transaction.
- **Evidence and audit not actually immutable:** enforced with triggers; `incidents.status`, `severity` and `is_valid` get CHECK constraints.
- **Evidence was non-deterministic** (unordered window); now sorted and includes anomaly, meter, building and severity.
- **Demo loader re-imported the same readings on every click** (fixed batch id and seed), flooding the quality log with thousands of duplicate issues that made every later window ineligible. It now loads once.
- **Simulator labels contradicted the docs:** labels for dropped or history-less readings were never removed, and `quality_ground_truth.json` was never written. Both fixed; the global RNG is no longer reseeded.

## Usability bugs fixed
- Demo data and CSV imports produced no incidents (analysis never ran). Analysis now runs automatically (about 1 s for 21k readings instead of 3.5 s).
- Incident list had no ORDER BY; now newest first. Entity and audit lists are ordered deterministically.
- Chart showed invalid readings and an arbitrary meter; it now plots valid readings of a stable meter and supports `meter_id` and `limit`.
- Excel BOM and header case/spacing broke imports; uploads with unknown meters, bad ids, reused batches or reversed ranges now return 404, 409, 422 or 400 instead of silent success or 500.
- Import and demo routes are sync, so a long import no longer freezes the event loop that serves dashboard polling. WAL mode stops writers blocking readers.
- Review, acknowledge, dismiss, resolve and unresolve accept an empty body; unknown incidents return 404.
- Upload size limit actually bounds memory; 500 responses no longer leak exception text.

## Verified by measurement
Detection results are unchanged by the refactor (1,272 anomalies, TP 225, FP 623 on seed 42). Recall rose from 0.983 to 0.996 only because three undetectable labels were removed from the ground truth.

## Follow-up (same day)
- **False alerts:** both detectors now confirm against the same hour on the same day type. Precision 0.265 -> 0.805, F1 0.419 -> 0.887, false alerts per building-week 9.69 -> 0.84, recall 0.996 -> 0.987.
- **Dashboard:** Dismiss, Resolve and Can't-resolve buttons with a reason dialog.
- **render.yaml:** the persistent disk and DB path were removed to match the free-plan service (no disk).
