# P0-1 - Sensitivity unification: verified, no bug

## Resolution

P0-1 was a false alarm. The initial analysis inferred from
`ARCHITECTURE.json` that `transparent._compute_sensitivity` reimplemented
constraint thresholds inline, because the graph showed no edge from
`_compute_sensitivity` to `evaluate_decision`.

The source disproves this. Every band-edge status is computed by calling
`build_context(...)` and then `evaluate_decision(ctx).status.value`, for
IT load, cooling load, and PUE. The graph does not trace calls made from
inside nested closures (`_status_it`, `_status_cooling`, `_status_pue`),
which is a tool limitation, not a code defect.

`scenario_analysis.analyze_sensitivity` is consistent: it re-runs the
full `decide_transparently` per step, which also uses
`evaluate_decision`. There is one evaluator, not two.

## Changes made

1. `transparent._sensitivity_status` extracted as a module-level helper.
   The three closures now delegate to it. Behavior is identical; the
   delegation is a single function the AST graph can now trace.
2. `tests/unit/test_sensitivity_equivalence.py` with four tests:
   - `evaluate_decision` is called once per band edge plus once for the
     base decision.
   - Every status recorded in the artifact was produced by
     `evaluate_decision`.
   - The sensitivity baseline matches the physical verdict in
     HYPOTHETICAL mode.
   - The artifact is reproducible.

## Import-path footnote

The spec test imports models from `ecofac.decision.*`, not from
`src.ecofac.decision.*`. `transparent.py` declares its pydantic fields
against the `ecofac.*` class objects. Importing from `src.*` would load
a second copy of every class; pydantic compares by identity, so it
rejects an instance of the "wrong copy" with a confusing
`Input should be a valid dictionary or instance of X` error.

This dual-package hazard exists throughout the repository (both
`src.ecofac.X` and `ecofac.X` resolve at runtime). A future cleanup
should add a `conftest.py` guard that rejects `src.ecofac` imports from
tests. Out of scope for P0-1.

## Out of scope

In TRUSTED mode, sensitivity runs before the operational second pass,
so its baseline is `base_decision.status`, not `decision.status`. That
is by design: derived operational flags include
`sensitivity_changes_verdict`, so running sensitivity against them
would be circular. No change proposed.
