7. Known limitations.

· PR-AUC: Without scikit-learn, the PR-AUC calculation is a simplified trapezoidal integration over available thresholds. In a production system, scikit-learn or an equivalent would provide a more rigorous calculation.
· Verification Caveats: Because we lack real weather/occupancy data, the engine outputs boilerplate caveats ("Weather and occupancy variations are not controlled for").
· Simulator Speed: Generating 21,600 points and running detection over them in Python takes a few seconds. This is fine for a synthetic test, but not production-scale.

8. Any unresolved risks.

· Evaluation Runner Runtime: The runner performs an anomaly detection scan over every single reading. With 21,600 readings, and each doing a SQL query, the evaluation may take a minute or two on CI. If it times out, we would need to optimize the batch size or limit the scan to a subset of readings.
